## 📌 1. Executive Summary

This document defines the production implementation plan for NALA's **Capability Cortex (CCX)**. By upgrading NALA from a static tool registry to a dynamic **Capability Dependency Graph (CDG)**, NALA will decouple *what the runtime needs to accomplish* from *how tools are concrete executed*.

### Core Objectives:
1. **Prerequisite Resolution**: Pre-evaluate all input/output capability dependencies prior to `TaskStep` dispatch.
2. **Dynamic Fallback & Degradation**: Automatically substitute failed or offline capabilities (e.g. `Web Search API` ➔ `Local Knowledge Cache`) without terminating the agent goal.
3. **Reliability-Aware Optimization**: Schedule capabilities by solving the cost-risk objective function in real time.
4. **Integration with NALA Engine**: Wire CCX directly into `nala_loop.py`, `sandbox.py`, and `nala_server.py`.

## 📐 2. Mathematical Formulation & Optimization Objective

Represent NALA's capability space as a Directed Acyclic Graph (DAG):

$$G = (C, E)$$

Where:
* $C = \{C_1, C_2, \dots, C_n\}$ is the set of capability nodes.
* $E \subseteq C \times C$ represents prerequisite dependencies between capabilities.

### Capability Node Definition ($C_i$):
$$C_i = (\text{Name}, \text{Inputs}, \text{Outputs}, \text{Cost}, \text{Reliability}, \text{Version}, \text{PermissionScope})$$

### Scheduler Objective Function:
For a given user goal requirement, the **Reliability-Aware Scheduler** selects the execution path $P^*$ that minimizes:

$$P^* = \arg\min_{P \in \text{Paths}(G)} \sum_{C_i \in P} \left( \alpha \cdot \text{Cost}(C_i) + \beta \cdot \text{LatencyMs}(C_i) + \gamma \cdot (1 - \text{Reliability}(C_i)) \right)$$

Subject to:
1. $\text{Inputs}(C_i) \subseteq \bigcup_{j < i} \text{Outputs}(C_j) \cup \text{InitialContext}$
2. $\text{PermissionScope}(C_i) \le \text{ExecutionContract}(C_t)$

### 🛠️ Component 1: Capability Dependency Resolver (`runtime/dependency_resolver.py`)

* **Purpose**: Inspects task steps and builds an active dependency chain before invoking tools.
* **Key Features**:
  * **Input/Output Type Checking**: Validates that step inputs match outputs generated by upstream nodes.
  * **Prerequisite Validation**: Verifies dependencies before handing tasks to `executor.py`.
  * **Cycle & Deadlock Prevention**: Enforces topological sorting via Depth-First Search (DFS).

---

### 🔄 Component 2: Dynamic Fallback & Graceful Degradation Engine (`runtime/composition_engine.py`)

* **Purpose**: Provides automatic capability substitution when a tool encounters network failure, rate limiting, or permission denial.

### 📐 Component 3: Production Data Schema (`schemas/capability_schema.py`)

* **Purpose**: Strict Pydantic v2 data models for node and edge definitions.

```python
from pydantic import BaseModel, Field
from typing import List, Dict, Optional

class CapabilityNode(BaseModel):
    capability_id: str = Field(..., description="Unique capability identifier")
    name: str = Field(..., description="Human readable name")
    version: str = Field(default="1.0.0", description="Semantic version string")
    inputs: List[str] = Field(default_factory=list, description="Required input schema keys")
    outputs: List[str] = Field(default_factory=list, description="Produced output schema keys")
    latency_ms: float = Field(default=50.0, description="Expected average latency in ms")
    reliability: float = Field(default=0.98, ge=0.0, le=1.0, description="Historical success rate")
    cost_tokens: float = Field(default=0.0, description="Estimated token/API execution cost")
    permission_scope: str = Field(default="READ_ONLY", description="Required permission scope")

class CapabilityEdge(BaseModel):
    parent_capability_id: str
    child_capability_id: str
    dependency_type: str = Field(default="HARD_PREREQUISITE") # HARD_PREREQUISITE | SOFT_ENHANCEMENT
    confidence: float = Field(default=1.0, ge=0.0, le=1.0)
```
